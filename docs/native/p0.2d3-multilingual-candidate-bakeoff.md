# P0.2d3 multilingual local-model candidate bake-off

Status: diagnostic experiment only. This work does not select a production
model, close the physical-device issue, or enable a local-model route.

## Subsequent reporting correction

The archived reports below are historical raw evidence and have not been rewritten.
Their `validText` classification is incorrect for 22 Gemma 270M records: these
ended with `finishReason=cancelled` and `generatedTokenCount=96`, the configured
cap. They are interrupted/token-budget-exhausted generations, not successful
complete text. The corrected executor detects exhaustion independently of the
runtime stop reason and rejects cancelled partial output below the cap. Thus the
historical 32/32 valid-text total must not be used as an execution acceptance claim.
The quality rejection remains unchanged.

The prompt/factory probes below do not exclude conversion, tokenizer, numerical,
or shared-runtime defects: no independent reference runtime or higher-precision
control was preserved. Their causal statements should be treated as hypotheses.
See the [reference experiment](../../native-ios/TranslationReferenceExperiment/README.md)
for the comparison that addresses these gaps.

For a concise continuation brief, see the [next-agent handoff](p0.2d3-next-agent-handoff.md).

## Question

After the Qwen3-0.6B functional run failed the translation-quality review, test
the most plausible sub-1B/1B multilingual candidates against the same bounded
Indonesian -> Polish corpus:

1. `mlx-community/gemma-3-1b-it-qat-4bit` — Gemma 3 1B IT QAT 4-bit;
2. `mlx-community/Qwen3.5-0.8B-MLX-4bit` — Qwen3.5 0.8B 4-bit;
3. `mlx-community/gemma-3-270m-it-4bit` — Gemma 3 270M IT 4-bit lower-bound
   baseline.

The catalog's approximate published weight sizes are 733 MB, 625 MB, and 151
MB respectively. They are planning estimates, not integrity or peak-memory
measurements. All three use the existing 1.5 GiB (`1,610,612,736` byte)
screening budget. Gemma redistribution terms must be reviewed separately from
the Apache-2.0 Qwen candidate.

TranslateGemma 4B is intentionally not in this run: its approximately 2.18 GB
4-bit weights already exceed the current budget before runtime overhead, and
the measured Qwen run showed that weight size is not a proxy for resident
memory. It can be a separately scoped quality reference if the memory ceiling
is relaxed.

## Provisioning boundary

Download or transfer each exact MLX snapshot outside the benchmark process. Do
not add model weights to Git. The benchmark accepts only a local directory and
checks for:

- `config.json`;
- at least one `.safetensors` file (all shards are included when present); and
- one supported tokenizer file (`tokenizer.json`, `tokenizer.model`,
  `spiece.model`, or `sentencepiece.bpe.model`).

The Qwen3-0.6B `--model-dir` path remains the strict, repository-pinned verifier.
The P0.2d3 candidate catalog is deliberately marked `researchUnpinned` until an
operator records an immutable revision and complete size/checksum manifest for
each snapshot. A successful local-folder check must not be described as exact
snapshot provenance.

## Run

From `native-ios/QwenMLXDiagnosticAdapter`:

```bash
swift run --configuration release qwen-mlx-benchmark \
  --candidate gemma-3-1b-it-qat-4bit=/absolute/path/gemma-3-1b \
  --candidate qwen3.5-0.8b-4bit=/absolute/path/qwen3.5-0.8b \
  --candidate gemma-3-270m-it-4bit=/absolute/path/gemma-3-270m \
  --output-dir /absolute/path/p0.2d3-bakeoff \
  --corpus functional \
  --execution-environment macos-arm64-local \
  --source-revision "$(git rev-parse HEAD)" \
  --timeout-seconds 120
```

`--candidate` may be repeated, but each candidate ID may appear only once. Add
an operator-recorded snapshot revision as `ID@REVISION=PATH` when one is known;
the revision is then carried into that candidate's report. If `--corpus` is
omitted for a multi-candidate invocation, the command defaults to the
functional corpus. The functional corpus currently contains the same 32
synthetic records used by the Qwen CI/device harness, including context-free
and bounded-context pairs.

The output directory contains `bakeoff.json`, `summary.md`, and one
`candidates/<candidate-id>/` report per successfully verified candidate. A
missing or failed candidate is retained in `bakeoff.json` and the command exits
non-zero, so an incomplete comparison cannot look like a pass.

## Review and decision gates

Review every raw output against the fixture's intended meaning and preservation
notes. Score meaning, hallucination, Polish fluency, tone/preservation, and
context benefit separately. The summary intentionally reports `unreviewed` for
quality; execution success, output validity, quality, and physical-device
acceptance remain different outcomes.

The report records `getrusage(RUSAGE_SELF).ru_maxrss` as a process high-water
resident-memory signal when available. Because candidates run in one process,
that value is not an attributed per-model peak. Run each candidate in an
isolated process and capture a named device/Instruments measurement before using
memory as an acceptance gate. No macOS run supplies physical-iPhone evidence.

If neither Gemma 3 1B nor Qwen3.5 0.8B clears the meaning and hallucination
hard gates, stop searching generic sub-1B chat models and open a separately
scoped specialized/distilled Indonesian <-> Polish translation experiment.

untranslated text, invented events, and repeated meta-instructions receive a

## Follow-up diagnosis: prompt and runtime probes

Two local-only probes separated prompt pressure from model capability. The
production structured prompt measured roughly 346--387 input tokens, while a
minimal direct prompt measured 27--34 tokens. Shrinking the prompt did not make
Qwen3.5 reliable across the 32-fixture corpus; examples included `Jako już
dojeść.`, `Wczór w ramach pory wczór.`, `Mamie, ożat, wchodzą do domu.`, and the
unchanged Indonesian `Kamu ga jadi berangkat?`. Prompt length is therefore a
contributor, but not the primary explanation.

The Qwen3.5 snapshot declares `Qwen3_5ForConditionalGeneration` and includes a
vision configuration. Loading that same local snapshot through the VLM factory
instead of the LLM factory changed the output but did not restore translation:
for `Aku sudah sampai di rumah.`, the LLM/current path returned `Widok na mnie,
w domu.`, the VLM/current path returned `Widokam na zameł w domu.`, and the
VLM/minimal path returned `Widok na mo na mo.`. The runtime choice is therefore
not a sufficient fix. Non-elevated macOS probes also hit a host Metal
initialization crash before inference; elevated runs completed, so that failure
is an execution-environment issue rather than evidence of better model quality.

The canonical run used non-greedy decoding (`temperature=0.7`, `top-p=0.8`,
`top-k=20`). Repeated probes of the same fixture varied substantially, which
adds sampling instability to the failure pattern. Greedy decoding reduced that
variance but still produced incorrect Qwen text such as `Jako już jestem na
domu.`; decoding settings influence the surface form, not the underlying
Indonesian -> Polish capability.

The probes used temporary environment switches that have been removed from the
checked-in harness. Their key observations are transcribed here and in the
next-agent handoff; the disposable probe directory and downloaded model caches
were cleaned after the run. The canonical evidence for this decision is the
32-fixture export above.

## Decision

Reject all three candidates for this Indonesian -> Polish contextual-translation
use case. No candidate advances to isolated physical-iPhone validation, and no
production routing changes. Stop the generic sub-1B chat-model search and open a
separately scoped specialized or distilled Indonesian <-> Polish translator
experiment. Issue #118's result is diagnostic only; #4 and #104 remain open
because their physical-device and production-acceptance criteria are not met.
