# P0.2d4 reference controls for Indonesian → Polish

Status: diagnostic evaluation complete; no candidate accepted. Related to #120. No production route
or physical-device acceptance is enabled by this work. The reverse direction is
not evaluated.

## Local Xcode and simulator validation

Final validation uses local Xcode and the simulator, as requested; CI outcomes
are not its basis. See the [sanitized result](p0.2d4-reference-controls/local-validation/summary.json).
On clean source `5b887817873e7ec40f9d797b574e22e670f1ad79`, Xcode 26.6
(`17F113`) built both the native app and benchmark harness. The native app launched
on an iPhone 17 Pro Max simulator running iOS 26.5 (`23F77`), and its diagnostics
screen was visually inspected. All **28 adapter tests passed on that simulator**,
with no failures or skips, including the at-cap/below-cap cancellation regression.

The real-model smoke attempt produced **no inference result**. The pinned MLX
runtime aborted with `SIGABRT` while evaluating `MTL::Architecture::name()` inside
`mlx::core::metal::Device::Device()`: libc++ detected a null string pointer. Neither
the smoke report nor the functional report was created. This is a local simulator
runtime-initialization failure, not another translation-quality score, and does
not invalidate the separate macOS reference runs. Simulator tests/builds do not
supply physical-iPhone evidence.

For Xcode 26.6, select a specific simulator destination instead of applying
`-sdk iphonesimulator` globally: the latter built the host-executed Swift macro
as an iOS Simulator binary. The successful build used `ONLY_ACTIVE_ARCH=YES` and
per-command `-skipPackagePluginValidation -skipMacroValidation` for the verified
pinned dependencies. No global trust setting or repository gate was changed.

Run from `native-ios/QwenMLXDiagnosticAdapter` to reproduce the simulator tests:

```sh
xcodebuild -scheme QwenMLXDiagnosticAdapter-Package \
  -destination 'platform=iOS Simulator,id=<local-simulator-id>' \
  -skipPackagePluginValidation -skipMacroValidation \
  -only-testing:QwenMLXDiagnosticAdapterTests \
  CODE_SIGNING_ALLOWED=NO ONLY_ACTIVE_ARCH=YES test
```

Local Gitleaks 8.24.3 and 8.30.1 tests verify that the narrow allowlist permits
the exact public revision while still detecting other findings in the same path.
The reference-export audit verifies all 248 archived rows, excluding the 32-row
invalid NLLB tokenizer run from quality evidence. The full `.xcresult` bundles and
crash report are kept outside Git to avoid publishing simulator identifiers and
host paths; the committed summary retains test names, outcomes and relevant frames.

## Findings established so far

- The original global Gitleaks allowlist could skip entire evidence paths. It
  now uses rule-scoped AND matching for exact public hashes. Global AND alone was
  insufficient: 8.30.1 still prefiltered the path, while CI's 8.24.3 ignored the
  global-array syntax. Both scanner versions must detect synthetic noncredentials
  in the evidence path while permitting only the exact known revision hashes.
- Archiving multiple JSON files exposed a pre-existing hook bug: `json.tool`
  interprets a second filename as output, potentially overwriting raw evidence.
  The hook now validates every passed file read-only. The affected working copy
  was restored byte-for-byte from its external original before validation.
- The Swift executor now rejects cancelled partial output and detects the token
  cap independently of the runtime's stop reason. All 28 adapter tests pass,
  including the at-cap and below-cap cancellation regression.
- Python MLX reproduces poor Indonesian→Polish output with the exact previously
  tested Qwen3.5 4-bit snapshot. Official higher-precision Qwen weights in
  Transformers also fail basic translations. This weakens both the Swift-only
  and quantization-only explanations; it does not prove numerical parity or the
  absence of all runtime defects.
- The first NLLB reference run was invalid: Transformers 5.3.0 AutoTokenizer
  returned generic TokenizersBackend and emitted an unknown source-language
  token. Explicit NllbTokenizer produces `ind_Latn` as the first token; the harness
  now asserts this and the Polish target ID. The invalid run is excluded from
  every model-quality count.
- Dedicated translation models improve basic sentence translation but remain
  unreliable on slang, particles, negation and omitted subjects. Both also change
  “meeting postponed” into “meeting cancelled,” a meaningful error that fluent
  Polish would otherwise hide.
- Concatenating context is not a functioning target-only adapter. Both dedicated
  models omit targets or return context text. These probes are evidence about this
  input strategy, not proof that no context-aware architecture could work.

## Interpretation and limitations

There are 24 unique synthetic source messages, expanded to 32 rows with eight
context pairs. Source-only duplicate rows are controls, not independent test
cases. The intended-meaning hints sometimes name Rina even when the input does
not: source-only scores do not penalize absence of that unavailable information.
Polish grammatical gender defaults are recorded as a preservation limitation,
not automatically treated as invented people.

The primary source-only comparison uses greedy Qwen and five-beam M2M100/NLLB.
Greedy dedicated-model exports are retained as decoding controls. Results from
different prompts, runtime versions and precisions are not a numerical-parity
test. Official Qwen BF16 weights were evaluated with float32 CPU arithmetic;
this does not reconstruct pre-quantization training weights at greater precision.

Runs accept only verified local snapshots, enable Hub/Transformers offline mode,
and record full artifact hashes, source SHA/dirty state, script/corpus hashes,
actual model input, runtime versions, output text and available token IDs. Offline
mode is not an OS network-isolation test. Separate processes make RSS attributable
to a run, but macOS process RSS is not iPhone memory acceptance. Concurrent host
workloads make timings unsuitable for a performance ranking.

## Recommendation

Do not advance these configurations to physical-device acceptance testing yet.
The important failures are semantic, so phone memory optimization cannot repair
them. Keep M2M100 as a permissively licensed sentence-translation baseline and
NLLB as a noncommercial research comparator. Neither satisfies the chat contract.

The next distinct experiment should establish a stronger translation-specialized
quality ceiling on a Mac, then investigate a licensed pair-specific small model
or a context-aware translation adapter against a held-out corpus. TranslateGemma
4B is a possible quality reference, subject to model access and terms review;
its archived 4-bit weight estimate already exceeds the current phone budget.
Do not distill NLLB outputs into a commercial product without resolving rights.
Do not add corpus-specific slang replacements and call that generalization.

M2M100 is MIT; Qwen is Apache-2.0; NLLB is CC-BY-NC-4.0 and its model card
describes research use. Weights remain outside Git. No candidate is approved for
distribution by this experiment.

## Reproduction

See [reference harness](../../native-ios/TranslationReferenceExperiment/README.md).
Acceptance runs must identify a clean source commit. The eight-record context
corpus is the exact subset of the archived P0.2d3 Qwen report whose `contextMode`
is `bounded`; the report's old outputs and meaning hints are never model inputs.

The [per-case quality ledger](p0.2d4-reference-controls/quality-review.md) reviews
all primary source-only outputs and the eight context probes. The semantic gate
counts over 24 unique inputs are M2M100 9/24, corrected NLLB 10/24, Qwen Python
MLX 3/24 and official higher-precision Qwen 2/24. Every contextual input strategy
has 0/8 usable target-only translations. Scores are an agent review, not a claim
of independent bilingual human validation or production certification.

Raw reports are under [p0.2d4-reference-controls](p0.2d4-reference-controls).
The `nllb-invalid-tokenizer.json` file is explicitly excluded. All other exports
come from clean committed source and completed the requested fixture count.
For the Python MLX wrapper, token-limit metadata is unavailable (`null`), so
`completed` means the loop returned all rows, not that every output ended cleanly
or passed quality. The obvious repeated-text failure is scored as such.
