# P0.2 Qwen3-0.6B local-model validation

Status: P0.2a contextual-request contract is merged; P0.2b adds an isolated,
local-only MLX diagnostic adapter and reproducible provisioning boundary.
Translation quality and physical-device validation remain pending.

Parent roadmap issue: #4

## Candidate

`Qwen/Qwen3-0.6B` is the first general multilingual model to validate for the
local fallback. Its official model card describes a 0.6B-parameter model with
100+ languages and translation support, and publishes it under Apache-2.0.

The Apple-oriented MLX conversion
[`mlx-community/Qwen3-0.6B-4bit`](https://huggingface.co/mlx-community/Qwen3-0.6B-4bit)
has a 335 MB `model.safetensors` file. That is a downloadable weight size, not
peak resident memory or a measured iPhone latency result.

## Runtime decision

Use the existing `MultilingualLocalModel` seam in
`WhatsAppTranslator/TranslationEngineCore.swift`. The diagnostic runtime is
MLX Swift LM with the 4-bit MLX artifact. The package supports iOS versions
older than this app's iOS 26 deployment target, while the separate MLX
Foundation Models bridge requires newer APIs; P0.2 therefore uses plain MLX
APIs rather than `LanguageModelSession`.

No MLX dependency, model weights, or Qwen adapter is bundled in the production
app target. The diagnostic adapter is an isolated Swift package under
`native-ios/QwenMLXDiagnosticAdapter`. The model is therefore not a product
feature and must not be enabled in the production router from this document
alone.

## Context-aware request boundary (P0.2a)

`LocalMultilingualModelEngine` passes the original `TranslationRequest`
unchanged to `MultilingualLocalModel.translate(_:)`. The local-model boundary
therefore receives the request ID, revision, language pair, explicit
`sourceText`, and the complete versioned `TranslationPrompt`, including its
immutable instructions and untrusted JSON context payload.

The explicit source message remains separate from the serialized prompt. A
model implementation must read `request.sourceText` rather than guessing the
source text by decoding `prompt.untrustedInput`. Plain-text
`TranslationTextProvider` implementations remain intentionally context-free;
this change does not imply that the two-step provider consumes conversation
context.

Regression tests record the request at the local-model boundary and cover
recent turns, speaker aliases, quoted-message context, summary data, identical
target text with different context, provenance, and adversarial payload strings
remaining data rather than replacing the immutable instructions. These are
structural contract tests, not real-model prompt-injection or translation-
quality evidence.

## Diagnostic MLX adapter and provisioning boundary (P0.2b)

P0.2b pins direct package inputs to MLX Swift LM 3.31.3 and Swift Transformers
1.3.4. The final PR must also commit the complete `Package.resolved` produced by
CI before #102 is considered ready to merge.

The model manifest pins the MLX snapshot to:

- repository: `mlx-community/Qwen3-0.6B-4bit`
- revision: `73e3e38d981303bc594367cd910ea6eb48349da8`
- tokenizer/chat-template revision: the same immutable snapshot
- quantization: 4-bit, group size 64
- `model.safetensors`: 335,450,584 bytes
- weight SHA-256:
  `392e8d466d56100ada00eb82031fb854297fc9e389b7d303eba3af114e87bce2`

`QwenMLXArtifactVerifier` requires the runtime config/tokenizer files and verifies
the exact weight size and SHA-256 before it creates
`QwenMLXVerifiedArtifacts`. The diagnostic model accepts only that verified
value. The repository ignores the package-local `.models/` directory and does
not commit model weights.

Artifact acquisition is explicitly outside inference. The MLX implementation
loads only from the verified local directory via
`LLMModelFactory.loadContainer(from:using:)`; no downloader or remote model ID is
available on that path. Missing artifacts fail closed instead of triggering a
network request.

The adapter requires the explicit request source text, applies source/prompt
byte limits, and uses the complete contextual `TranslationPrompt` as the model
input. Generation has a fixed token cap and requests Qwen's chat-template
`enable_thinking = false` context. The loaded model container may be reused, but
every translation creates a fresh `ChatSession` so transcript/KV state cannot
leak across benchmark cases or chats.

The package returns raw non-empty generation only. It does not classify
thinking-only/truncated output or translation quality; those are #103 concerns.

## Validation checklist

- [x] Forward the complete versioned `TranslationRequest` through the
      replaceable local-model boundary and cover the handoff with deterministic
      host-independent tests (#100 / P0.2a).
- [x] Add and run a temporary MLX Swift loading/generation harness without
      committing model weights, then remove it after the experiment (#92/#93).
      See [macOS CI smoke results](qwen3-mlx-smoke-results.md).
- [x] Add an isolated plain-MLX diagnostic adapter with a verified local
      provisioning boundary, bounded inputs/generation, fresh per-request
      sessions, and no hidden model download path (#102 / P0.2b). This checkbox
      is satisfied only when the PR's final locked dependency graph and CI pass.
- [ ] Run the original unencoded P0.1 fixtures through the adapter, including
      slang, omitted subjects, code-switching, quoted replies, and context
      windows 0/3/8/16; export execution/output-validity results (#103).
- [ ] On the connected physical iPhone, record cold load, warm latency,
      tokens/second when available, peak memory, thermal/battery impact,
      cancellation, and offline behavior (#104).
- [ ] Review translation quality separately from runtime availability with a
      native Polish speaker or an agreed quality rubric (#104).
- [ ] Compare against the OPUS-MT two-step baseline and direct M2M100 control in
      separately scoped comparison work.
- [ ] Enable a local-model router only after physical-device and quality gates
      select a candidate; otherwise keep the explicit unavailable-model fallback.

## Current decision

Research selection: **Qwen is a candidate, not selected product infrastructure**.

macOS CI smoke: **PASS for model loading and non-empty text generation only**.
The 16-token English probe produced a thinking fragment, not a final `OK` or an
Indonesian -> Polish translation. The [archived report](qwen3-mlx-smoke-results.md)
records the output, timings, source revision, and disposable-harness cleanup.

P0.2a contract: **PASS** — the local-model boundary receives the complete
contextual request with deterministic regression coverage.

P0.2b adapter: **IMPLEMENTED, FINAL PR VALIDATION PENDING** — the new package is
isolated from the production app and host-independent core package. Do not
upgrade this status to runtime/quality PASS until the locked dependency graph
and final-head CI are green. No model weight or inference result is claimed.

Physical-device acceptance: **PENDING**. Do not close issue #4 or claim
Indonesian support until #103/#104 supply comparable translation and real-device
evidence.
