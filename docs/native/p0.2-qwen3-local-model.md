# P0.2 Qwen3-0.6B local-model validation

Status: P0.2a contextual-request contract, P0.2b isolated MLX adapter, and P0.2c shared benchmark/export are merged. P0.2d physical-device evaluation is split into #108 instrumentation/evaluation-contract preparation and #109 the actual iPhone run plus candidate decision.

Parent roadmap issue: #4

## Candidate

`Qwen/Qwen3-0.6B` is the first general multilingual model being validated for the local fallback. Its official model card describes a 0.6B-parameter model with 100+ languages and translation support and publishes it under Apache-2.0.

The Apple-oriented MLX conversion `mlx-community/Qwen3-0.6B-4bit` has a 335 MB `model.safetensors` file. That downloadable weight size is not peak resident memory and is not a measured iPhone latency result.

## Runtime decision

Use the existing `MultilingualLocalModel` seam in `WhatsAppTranslator/TranslationEngineCore.swift`. The diagnostic runtime is MLX Swift LM with the 4-bit MLX artifact. The package supports this app's deployment target without requiring the separate Foundation Models bridge, so P0.2 uses plain MLX APIs rather than `LanguageModelSession`.

No MLX dependency, model weights, or Qwen adapter is enabled in the production router. The diagnostic adapter remains an isolated Swift package under `native-ios/QwenMLXDiagnosticAdapter`. The candidate must not become product infrastructure until the physical-device and quality gates select it.

## Context-aware request boundary (P0.2a)

`LocalMultilingualModelEngine` passes the original `TranslationRequest` unchanged to `MultilingualLocalModel.translate(_:)`. The local-model boundary therefore receives request ID, revision, language pair, explicit `sourceText`, and the complete versioned `TranslationPrompt`, including immutable instructions and untrusted JSON context payload.

The explicit source message remains separate from the serialized prompt. A model implementation reads `request.sourceText` rather than reconstructing source text from `prompt.untrustedInput`. Plain-text `TranslationTextProvider` implementations remain intentionally context-free.

Regression tests cover recent turns, speaker aliases, quoted-message context, summary data, identical target text with different context, provenance, and adversarial payload strings remaining data rather than replacing immutable instructions. These are structural contract tests, not real-model translation-quality evidence.

## Diagnostic MLX adapter and provisioning boundary (P0.2b)

Direct package inputs are pinned to MLX Swift LM 3.31.3 and Swift Transformers 1.3.4. The committed `Package.resolved` is the authoritative full SwiftPM resolution.

The model manifest pins:

- repository: `mlx-community/Qwen3-0.6B-4bit`
- revision: `73e3e38d981303bc594367cd910ea6eb48349da8`
- tokenizer/chat-template revision: the same immutable snapshot
- quantization: 4-bit, group size 64
- `model.safetensors`: 335,450,584 bytes
- weight SHA-256: `392e8d466d56100ada00eb82031fb854297fc9e389b7d303eba3af114e87bce2`

`QwenMLXArtifactVerifier` requires the runtime configuration/tokenizer files and verifies the exact weight size and SHA-256 before producing `QwenMLXVerifiedArtifacts`. The diagnostic model accepts only that verified value. The repository ignores package-local `.models/` and does not commit model weights.

Artifact acquisition is outside inference. The MLX implementation loads only from the verified local directory through `LLMModelFactory.loadContainer(from:using:)`; no downloader or remote model ID is available on that path. Missing artifacts fail closed instead of triggering network access.

The adapter requires explicit source text, bounds source/prompt bytes, and uses the complete contextual `TranslationPrompt`. Generation is capped and requests Qwen's `enable_thinking = false` chat-template context. The loaded model container may be reused, but each translation gets a fresh `ChatSession` so transcript/KV state cannot leak across fixtures or chats.

## Shared benchmark/export (P0.2c)

Issue #103 is complete. The diagnostic runner consumes the source-controlled unencoded P0.1 fixtures directly, including context windows 0, 3, 8, and 16. It keeps execution state, output validity, translation quality, and physical-device acceptance separate.

The report/export distinguishes valid output, empty text, thinking-only output, truncation, cancellation, timeout, and input-budget failure. Individual results are deterministic JSON records suitable for human review; the summary is Markdown. Model/configuration provenance, prompt version, fixture identity, output/errors, and available runtime measurements stay attached to each run.

A non-empty result is not automatically a quality pass.

## Physical-device instrumentation contract (P0.2d1 / #108)

The pinned MLX Swift LM 3.31.3 API exposes structured completion information through `ChatSession.streamDetails`. The diagnostic path records generated-token count, prompt/first-token time, generation time, tokens/second, and stop reason directly from that verified API. It also records whether model loading was cold and the monotonic model-load duration.

The benchmark report carries the predeclared `p0.2d1-v1` performance and quality contract plus a physical-device evidence object. Non-device runs keep that object explicitly `notRun`; macOS or Simulator success is not physical-device evidence.

The screening thresholds, quality rubric, and exact evidence-capture sequence are committed in [`p0.2-physical-device-evaluation-plan.md`](p0.2-physical-device-evaluation-plan.md) before the candidate is scored or selected.

## Current decision

Research selection: **Qwen is a candidate, not selected product infrastructure**.

macOS smoke: **PASS for model loading and non-empty text generation only**. The archived 16-token English probe produced a thinking fragment, not a completed instruction-following or Indonesian -> Polish result.

P0.2a request contract: **PASS**.

P0.2b isolated adapter/provisioning: **PASS for implementation and CI boundary validation**. This is not an on-device quality/performance pass.

P0.2c benchmark/export: **PASS for reproducible diagnostic execution/export**. It does not select the candidate.

P0.2d physical-device acceptance: **PENDING**. #108 prepares the measurement contract; #109 must supply actual iPhone evidence and the accept/reject/continue-evaluation decision. Do not close #4 or claim the custom-model acceptance criterion until those requirements are genuinely satisfied.
